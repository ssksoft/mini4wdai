# ミニ四駆コース部品 for Unreal Engine

3Dスキャン（Scaniverse）から寸法を割り出し、**走行用に作り直した部品**です。スキャンのメッシュは壁がほとんど欠けていて、そのままでは当たり判定に使えません。そこで、測った寸法から形状を作り直しました。テクスチャ付きのスキャンメッシュも、位置を合わせて見た目用に同梱しています。

対象：タミヤ オーバルホームサーキット 立体レーンチェンジタイプ（2レーン、レーン幅11.5cm、フェンス高5cm）

## 部品

| UEアセット | 実物 | スキャン元ファイル |
|---|---|---|
| `SM_Straight` | ストレート（46.5cm） | 0f355a50 |
| `SM_Curve45_L` / `SM_Curve45_R` | 45°カーブ（左回り／右回り。実物は同じ部品の向き違い） | 2ac27cb1（青）, 6968db46（緑） |
| `SM_LaneChange_Base` | レーンチェンジの土台（スロープ＋地上S字レーン） | 1f147f5d（1-2）, 90745ad7（2）※形状は同じ |
| `SM_LaneChange_Bridge` | レーンチェンジの立体橋（S字・クリアカバー付き） | 6a42af1d |

各部品に入っているもの
- 見た目用メッシュ（マテリアルスロット `M_Track`、橋だけ `M_Cover` もあり）
- **当たり判定 `UCX_`**：床と壁を凸形状に分けたもの。高速で走っても抜けないよう、外側の壁と床裏だけ 1cm 厚くしてある
- **接続点ソケット**：`In`（始点）と `Out`（終点）。X方向が進行方向。土台には橋を載せる `BridgeMount` もある
- 単位は cm。原点は `In` ソケットの位置

## フォルダ構成

```
fbx/          作り直した部品（ここが本体）＋ parts_manifest.json
scan_fbx/     スキャン見た目メッシュ（背景除去・位置合わせ済み、テクスチャ埋め込み）
ue/           Unreal Editor 用 Python スクリプト
generator/    部品を作り直すための生成スクリプト（寸法を変えたいとき用）
preview/      プレビュー画像・検証結果
```

## いちばん簡単な手順（まとめて実行）

UE の Output Log（Cmd を `Python` にする）で、次の1行を実行してください。
```
py "C:/Users/sasat/Desktop/work/Mini4WDAI/mini4wdai/3dsim/mini4wd_course/ue/setup_in_ue.py"
```
これで次の処理が順番に進みます。
1. 新しいレベル `/Game/Mini4WD/Maps/Mini4WD_Oval` を作る
2. 部品・マテリアル・当たり判定・ソケットを取り込む
3. 公式と同じオーバルを組む
4. カメラを向けて保存する

## UE での手順（個別に実行する場合、UE 5.x）

1. **Edit > Plugins** で `Python Editor Script Plugin` を有効にし、エディタを再起動する
2. このフォルダを丸ごと、PCの好きな場所に置く（`ue/` と `fbx/` の位置関係はそのまま）
3. **部品のインポート**（初回だけ）：`Tools > Execute Python Script...` で `ue/import_parts.py` を実行
   - `/Game/Mini4WD/Parts` に部品、`/Game/Mini4WD/ScanVisuals` にスキャン見た目、`/Game/Mini4WD/Materials` に黒・緑・青・クリアのマテリアルと物理マテリアルができる
   - Output Log に `convex hulls 4 / 4  sockets OK` のように出れば成功
4. **コースを組む**（どちらか好きな方で）
   - まとめて組む：`ue/build_course.py` を実行。初期設定は実物と同じオーバル（216×123cm）
   - 1つずつつなぐ：最後の部品を選択した状態で、Output Log（Cmd を `Python` にする）から実行
     ```
     py "C:/…/mini4wd_course/ue/append_part.py" S
     py "C:/…/mini4wd_course/ue/append_part.py" L:blue
     ```
     追加した部品が自動で選択されるので、同じコマンドを繰り返すとどんどんつながる

### レイアウトの書き方

| 記号 | 部品 |
|---|---|
| `S` | ストレート |
| `L` / `R` | 45°カーブ（左／右）。`L:green`、`R:blue` のように色も指定できる |
| `LC_UP` | レーンチェンジ（上り）。橋も自動で付く |
| `LC_DOWN` | レーンチェンジ（下り）。必ず `LC_UP` の直後に置く |

例：`py ".../build_course.py" "LC_UP,LC_DOWN,L,L,L,L,S,S,L,L,L,L"`

コースが閉じたかどうかは Output Log に出ます（`closed loop (gap 0.000 cm)`）。
`build_course.py` 冒頭の `USE_SCAN_VISUALS = True` にすると、見た目がスキャンテクスチャに切り替わります（当たり判定は作り直した部品のまま、非表示で残ります）。

## 寸法（`generator/track_params.json`）

| 項目 | 値 | 根拠 |
|---|---|---|
| レーン幅 | 115 mm | カタログ値。スキャンの壁ピッチ 116〜117mm と一致 |
| フェンス高 | 床から 50 mm | カタログ値。スキャンとも一致 |
| 床面の高さ | 7 mm | スキャン |
| ストレート長 | 465 mm | スキャン（460〜466mm）とカタログ全長 2160mm から逆算 |
| カーブ | 45°、壁の半径 380 / 497 / 614 mm | スキャンの壁に当てはめた結果、残差の中央値 1.6mm |
| スロープ | 長さ 230mm で 59mm 上がる（約15°） | スキャン |
| 橋 | 長さ 440mm で 1レーン分横に移動、中央が 15mm 盛り上がる | スキャン（中央の盛り上がりは推定値） |

検証結果（`preview/` に画像あり）
- オーバルに組むと 216.0 × 123.0 cm になり、始点と終点のずれは 0
- 当たり判定の上で仮想の車を壁沿いに2周させたところ、どちらのレーンから出発しても落下・引っかかり・壁抜けなしで完走
  - レーンチェンジで内側と外側のレーンが正しく入れ替わる
  - 2周の距離は 998cm（カタログ値「2周で約10m」と一致）
- スキャンを各部品に重ねて形状を確認済み（`scan_vs_model_overlay.png`）

**省略しているもの**：床のスリット穴、部品どうしをつなぐジョイントの爪、橋の支柱の細かい形。
走行に影響しない部分です。必要なら `track_params.json` を変えて `generator/build_parts.py` を実行すれば、作り直せます。

## 寸法を直したいとき

1. 実物を定規で測る（スキャンより正確です）
2. `generator/track_params.json` を書き換える
3. `python generator/build_parts.py` を実行（必要なのは Python3 と numpy）
   - `fbx/` が更新される
4. UE で `import_parts.py` を実行し直す

組んだ状態の確認には `python generator/drive_test.py fbx "S,S,L,L,L,L,S,S,L,L,L,L" 1100` を使います（scipy も必要）。

## 車を走らせるときのヒント

- 実物のミニ四駆は約 5m/s で走るので、1フレームに 8cm 以上進みます。車側のボディは **Use CCD**（連続衝突判定）を ON にしてください
- 実物は壁をローラーで転がって曲がります。代わりに次のどちらかにすると安定します
  - 車の四隅に摩擦0の球コリジョンを付ける
  - 物理マテリアルを摩擦0にした「ローラー」コリジョンを付ける
- 一番簡単な試し方：物理ON の小さな箱（約16×10×4cm、0.13kg）に、毎Tick前方向へ力（Add Force）をかけ続ける
  - 壁に沿って周回するか確認できる

## 注意

- UEのスクリプトは UE 5.x 向けです。疑似環境でロジックは確認していますが、実際のUEエディタでは試していません
- インポート時は、`UCX_`／`SOCKET_` の命名規則が確実に効く従来のFBXインポーターに、一時的に切り替えて実行します
- 当たり判定かソケットが取り込まれなかった場合は、Output Log に警告を出して自動で補います
  - 当たり判定 → メッシュそのものを当たり判定に使う（Complex as Simple）
  - ソケット → `parts_manifest.json` から作る
- 部品の左右（どちらのレーンがスロープか）は、スキャンの向きから判定しています。もし実物と左右が逆なら教えてください

## ミニ四駆を走らせる（マッドレイザー／MAシャーシ）

1. 初回だけ、UE の Output Log（Cmd）で次を実行します。
   ```
   py "C:/Users/sasat/Desktop/work/Mini4WDAI/mini4wdai/3dsim/mini4wd_course/ue/car_setup.py"
   ```
   - 車をインポートしてスタート地点に置き、GameMode・カメラを設定します
   - キーボード操作用のスクリプトがエディタ起動時に自動で読み込まれるよう登録します（`Content/Python/init_unreal.py`）
2. ▶（Play）を押し、ゲーム画面を1回クリックして操作します。

| キー | 操作 |
|---|---|
| W / ↑ | アクセル（モーター ON） |
| S / ↓ | ブレーキ → 停止後は後退 |
| R | スタート地点に戻る |
| 1 / 2 | スタートレーンを外側／内側に切り替えてリセット |
| C | カメラ切替（後方追従／真上／コース脇） |
| M | モーター切替（ノーマル／トルクチューン相当／ハイスピード相当） |

画面左上に、速度・ラップ数・ラップタイム（W を押した瞬間から計測）が出ます。

**車のモデル**：公式値をもとに作っています。
- 全長156 × 全幅97 × 全高36 mm
- ホイールベース80 mm、トレッド59.5 mm、重量125.9 g
- 最低地上高2.2 mm、ギヤ比3.5:1、ローラー6個
- タイヤ径は約24 mm と仮定しています

**走る仕組み**
- 車体・ローラー・タイヤの当たり判定は Chaos 物理が計算します。どれも摩擦0なので、実車と同じく壁に沿って曲がります
- タイヤのグリップ（横方向）とモーター駆動力は、`ue/m4wd_drive.py` が毎フレーム加えています
- 数値は `m4wd_drive.py` の冒頭で調整できます
  - `MOTORS`：最高速・加速
  - `MU_TIRE`：タイヤの摩擦
  - `ROLL_DECEL`：惰性で走るときの減速

**制限**
- この操作スクリプトは、エディタ内の Play（PIE）でだけ動きます。単体起動やパッケージ化したゲームでは動きません
- 単体で動かすには、Blueprint か C++ への移植が必要です。C++ にする場合は Visual Studio が必要です

**描画設定の変更**
このPCでは、ハードウェアレイトレーシングと Lumen の描画中に GPU がハング（`DXGI_ERROR_DEVICE_HUNG`）しました。そのため、プロジェクト設定を次のように変更しています。

| 設定 | 変更後 |
|---|---|
| `r.RayTracing` | False |
| Lumen GI | なし |
| 反射 | SSR |
| 物理 | サブステップを有効化 |

元の設定は、元の場所（`Documents/Unreal Projects/MiniYonkuSim/Config/DefaultEngine.ini.bak_before_m4wd`）に残してあります。
